# Agent Hub Marketplace 布局重构设计

- Status：Approved design; pending implementation plan
- Date：2026-08-28
- Repository：bibit-agenthub-plugin

## 1. 目标

将 Agent Hub 的 Power 展示页重构为统一、易浏览的 Marketplace 风格，同时保持
现有 Store 数据契约和每页 20 个系列的分页语义不变。

本次重构包括：

- 统一“我的 Power”和“Power 市场”的顶部导航与筛选布局；
- 将“我的 Power”专有的 Agent 选择收进该页签的悬停菜单；
- 为范围、类型和 Tags 控件提供明确且一致的选中边框高亮；
- 以不同但克制的类型色区分 Skill、Plugin、MCP 和 Agent；
- 重排并放大 Power 卡片，改善版本、描述和 Tags 的信息层级；
- 使用左右箭头与可填写页码的居中分页栏；
- 宽屏每行最多展示 5 张卡片，并在窄屏逐级减少列数。

## 2. 非目标

本次重构不包含：

- 修改 `powers.list.v1` 请求或响应契约；
- 修改 Store、APC、APM、SDK 或开发 Mock 的业务语义；
- 修改每页固定 20 个 Power 系列的规则；
- 增加 Power 安装、下载、发布或管理功能；
- 抽取跨项目的完整 UI 组件库或设计系统；
- 修改 Agent Hub 设置页的功能行为。

## 3. 实现策略

采用定向组件重构。页面保留数据请求、筛选状态、快照和错误处理职责；筛选栏、
Agent 菜单、卡片和分页组件分别负责自己的展示和交互。类型配色通过共享 CSS 自定义
属性或 `data-power-type` 映射驱动，避免在多个组件中重复硬编码状态样式。

不采用纯 CSS 微调，因为 Agent 菜单、快速跳页和键盘交互需要明确的组件状态与测试
边界；也不构建完整设计系统，因为当前只有一个页面需要这些控件。

## 4. 页面结构

页面内容使用居中的最大宽度容器，纵向顺序为：

1. 页面标题；
2. “我的 Power / Power 市场”一级范围页签；
3. 类型与 Tags 独立筛选面板；
4. 加载、警告、错误或空结果状态；
5. Power 卡片网格；
6. 分页栏。

范围页签采用独立一级导航样式，类型和 Tags 位于其下方的筛选面板。切换范围时，
筛选面板、状态区、网格和分页栏的位置保持稳定。

内容容器和卡片网格整体居中。网格内部固定从左向右排列，因此最后一行不足 5 张
卡片时靠左，不对该行单独居中。

## 5. 筛选交互

### 5.1 范围与 Agent

“我的 Power”和“Power 市场”使用一级页签。当前页签通过边框或下划线、文字颜色和
焦点样式共同表达选中状态，不仅依赖背景色。

“我的 Power”同时是 Agent 菜单触发器：

- 鼠标悬停、鼠标点击或键盘聚焦/激活均可展开菜单；
- 菜单列出服务端 facets 返回的 Agent；
- 当前 Agent 在菜单中显示勾选标记，但页签文字始终保持“我的 Power”；
- 选择 Agent 后关闭菜单、清空 Tags、回到第 1 页并发起新请求；
- 切换到“Power 市场”再返回时，保留此前选择的 Agent；
- 若服务端 facets 不再包含当前 Agent，沿用现有回退规则选择 `bibit` 或首个 Agent；
- 菜单支持 Escape 关闭、方向键导航和清晰的键盘焦点。

Agent 菜单只在“我的 Power”页签上可用。“Power 市场”不显示空的 Agent 占位控件。

### 5.2 Power 类型

类型保持单选且不增加“全部”选项。四种类型使用稳定色系：

- Skill：紫色；
- Plugin：绿色；
- MCP：橙色；
- Agent：蓝色。

每个按钮具有自己的浅色背景和类型色文字。当前类型使用同色加粗边框和独立焦点环；
未选中项仍保留足够的类型辨识度。选择类型后清空 Tags、回到第 1 页并清除旧快照。

### 5.3 Tags

Tags 使用传统圆角标签按钮，支持多选 OR 语义。未选中标签使用中性底色和细边框；
选中标签使用当前 Power 类型的浅色背景和加粗边框，并保留 `aria-pressed` 状态。

标签区域允许换行，并设置最大高度。超过最大高度后在标签区域内部纵向滚动，不扩张
整个筛选面板。切换标签后回到第 1 页并清除旧快照。

## 6. Power 卡片

卡片使用统一尺寸与内部网格，内容层级为：

1. 左上角 Power 类型标识；
2. Power 名称；
3. 右上角版本选择；
4. 描述；
5. Tags。

版本选择只显示 `vMAJOR.MINOR.PATCH`，删除可见的 “Version” 字样，但通过
`aria-label` 保留可访问名称。切换版本时，描述和 Tags 必须同步更新。

描述使用只读文本容器而非 `textarea` 外观。描述区域采用固定高度，超出内容纵向
滚动。Tags 使用胶囊标签并位于卡片底部，区域高度固定；标签超出可用区域时允许内部
滚动，不能撑高卡片或改变同一行卡片的高度。

卡片采用已确认的柔和类型配色：白色到浅类型色的低饱和渐变背景、类型色边框、同色
类型标识和浅色 Tag。卡片与对应类型按钮使用同一色系。悬停时只轻微上浮并增强阴影，
不改变尺寸或周围布局。

## 7. 网格与响应式布局

卡片网格使用固定的目标卡片宽度和统一间距：

- 宽屏最多 5 列；
- 可用宽度降低时依次变为 4、3、2、1 列；
- 不为维持列数而把卡片压缩到影响可读性的宽度；
- 卡片网格容器居中，网格内各行从左侧开始排列；
- 每页 20 项时，五列布局最多为四行。

具体断点以目标卡片最小宽度、列间距和内容容器内边距计算，不依赖设备名称。

## 8. 分页

分页栏在卡片网格下方整体居中，形式为：

    ‹  第 [2] / 4 页  ›

行为规则：

- 首页禁用左箭头，末页禁用右箭头；
- 页码输入只接受整数；
- Enter 或输入框失焦时提交跳转；
- 输入值小于 1 或大于总页数时限制到合法范围；
- 空白或不能解析的输入恢复当前页，不发起请求；
- 筛选变化后页码输入与请求页码一同恢复为 1；
- 跳到大于 1 的页时沿用当前结果的 snapshot；
- 服务端返回 `reset_required` 时沿用现有逻辑清除 snapshot 并回到第 1 页。

## 9. 状态与数据流

`AgentHubPage` 继续拥有 `scope`、`agent`、`type`、`tags`、`page`、`snapshot`、重试
计数和请求状态。展示组件只通过 props 接收状态并发出语义化变更事件，不直接调用
Store。

数据流保持：

    用户操作
      -> 页面更新筛选或页码状态
      -> 取消旧请求并构造 ListPowersInput
      -> Store 返回 ready / reset_required / error
      -> 页面更新 facets、卡片、状态提示和分页

加载、警告、错误和空结果提示位于筛选面板与网格之间，并与内容区等宽。错误文案、
可重试判断、请求取消和过期响应保护保持现状。

## 10. 组件边界

- `AgentHubPage`：数据请求、页面状态、快照与错误处理、组件编排；
- `PowerFilters`：范围页签、Agent 菜单、类型按钮和 Tag 标签；可在文件内部拆分私有
  子组件，只有出现独立测试或复用价值时再创建新文件；
- `PowerCard`：版本状态、描述和 Tags 的同步展示、类型样式属性；
- `PowerPagination`：箭头状态、草稿页码、Enter/失焦提交和输入规范化；
- `agentHub.css`：页面布局、类型色变量、组件状态、响应式断点和滚动区域样式。

## 11. 可访问性

- 范围、类型和 Tags 的选中状态使用语义属性表达；
- Agent 菜单不依赖纯悬停，支持鼠标、触屏和键盘；
- 所有可交互元素具有可见的 `:focus-visible` 样式；
- 版本选择保留不可见但可访问的名称；
- 箭头按钮具有“上一页 / 下一页”名称，页码输入具有当前范围提示；
- 禁用状态同时通过原生 `disabled` 和视觉样式表达；
- 类型差异不只依靠颜色，还通过文本标识和边框状态表达。

## 12. 测试与验证

组件测试覆盖：

- 范围页签切换与选中状态；
- Agent 菜单展开、当前项勾选、选择、键盘关闭及切换市场后选项保持；
- 四种类型按钮、类型变化和选中边框对应的状态属性；
- Tags 多选、排序、去重和选中状态；
- 卡片版本号无可见 “Version” 文案，但仍可通过可访问名称操作；
- 版本变化时描述和 Tags 同步变化；
- 分页箭头、页码 Enter/失焦提交、非法输入恢复与上下界限制；
- 页面筛选、翻页、snapshot 和错误处理的原有行为不回归。

完成实现后运行：

    npm test
    npm run typecheck
    npm run build:dev
    git diff --check

通过浏览器预览额外检查五至一列布局、最后一行左对齐、滚动区域、菜单叠层、焦点环和
四种类型配色。实现属于行为变更，完成后按仓库规则在 `docs/Changelog.md` 添加一条
记录。

## 13. 现有工作区改动处理
